# M6 自动试玩、调参与 QA 报告

- 日期：2026-08-17
- 范围：1–4 名真人小孩槽位的自动机器人预检、单轴候选复测、PC 视觉与生产预览 QA
- 结论：自动验收通过；未发现隐藏坐标泄漏、软锁、输入卡死或永久重叠
- 边界：以下对局是确定性高技能机器人，不是真人试玩，不据此宣称最终平衡或发布完成

## 1. 实现结果

- 新增确定性机器人，使用正式 `DEFAULT_HOUSE_MAP`、正式 `MatchEngine` 和 60 Hz 规则推进；不是另一套简化战斗规则。
- 新增 1–4 名小孩的固定种子矩阵、可复现汇总命令和规则级终局/重叠/软锁断言。
- 新增 `child-hidden`、`child-playing`、`ghost-playing`、`low-battery`、`capture`、`protection`、`child-win`、`ghost-win` 八种浏览器状态。
- 测试钩子只在 Vite 开发模式安装；生产构建没有 `setState` 等捷径。
- 新增四张 Win32/Chrome 视觉基线，并保留画布像素、真实输入和真实联机测试。
- 真实 Socket.IO 服务逐一验证 2、3、4、5 人房：一名鬼、其余真人小孩、空余槽位由人偶补齐。
- `blur` 会同时释放 ESDF 与空格；浏览器测试验证角色停止且光束关闭。
- 导入墙成功后移除并释放灰盒回退几何，生产场景已初始化几何由 74 降为 30。

## 2. 自动机器人基线

命令：

```powershell
npm run test:balance -- --runs 24 --seed-base 8100 --out artifacts/m6-balance-baseline.json
```

每个人数 24 局，共 96 局。机器人会寻路、追逐、根据头灯迎战、在巡逻时扫灯、寻找低电电池，并通过正式碰撞系统经过门口。`有效时长`不含抓捕动画与保护期；首次/第三次抓捕时间是实际墙钟时间。

| 真人小孩 | 小孩胜率 | 平均有效时长 | 首次抓捕 | 第三抓捕到达率 / 时间 | 首次照中 | 有效照射 | 电池生成/局 | 收集率 / 等待 | 堵口事件/局 |
|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| 1 | 0% | 10.04s | 3.34s | 100% / 17.02s | 2.93s | 1.30s | 0 | — | 0 |
| 2 | 0% | 10.02s | 3.33s | 100% / 17.01s | 2.93s | 1.30s | 0 | — | 0 |
| 3 | 4% | 19.76s | 2.51s | 96% / 14.56s | 2.00s | 0.75s | 0.13 | 67% / 2.92s | 0.04 |
| 4 | 29% | 92.89s | 2.52s | 71% / 14.59s | 2.01s | 0.68s | 1.08 | 92% / 4.36s | 0.33 |

补充指标：

- 1–4 人所有 96 局墙体穿透为 0、永久重叠为 0、五秒全局软锁窗口为 0，最小真人间距分别为 0.96、0.96、0.91、0.90。
- 每名小孩平均头灯 `off/slow/fast/solid` 时间：1 人 `9.67/1.40/1.09/4.87s`；2 人 `13.34/0.70/0.55/2.44s`；3 人 `15.19/4.81/0.85/5.62s`；4 人 `21.35/47.42/7.89/22.50s`。
- 1–2 人局在电池出现前已结束；这是“鬼过早形成三次抓捕”的信号，不等于电池逻辑未工作。3–4 人局和独立规则测试都覆盖生成、保留、拾取和充满。
- 抓空次数为 0，说明机器人对距离和朝向的知识过于精确；这组数据不能评价真人是否看懂 350 ms 前摇和 1.2 s 抓空冷却。
- 自动机器人知道完整规则状态，不能模拟小孩无法沟通、误判鬼方向、鼠标操作误差与真人堵门意图，因此只作为回归/极端策略预检。

## 3. 单轴候选复测

只测试速度轴：鬼移动速度从已接受的 `3.96` 临时候选降至 `3.45`，小孩仍为 `3.60`；光束、伤害、电量、抓取、出生点和地图全部不变。相同 96 个种子复测：

| 真人小孩 | 基线 → 候选小孩胜率 | 基线 → 候选有效时长 | 候选首次抓捕 | 候选第三抓捕 | 候选有效照射 |
|---:|---:|---:|---:|---:|---:|
| 1 | 0% → 0% | 10.04 → 11.56s | 3.80s | 18.54s | 1.31s |
| 2 | 0% → 0% | 10.02 → 11.42s | 3.79s | 18.40s | 1.33s |
| 3 | 4% → 4% | 19.76 → 20.33s | 2.71s | 15.15s | 1.58s |
| 4 | 29% → 29% | 92.89 → 93.30s | 2.75s | 15.18s | 1.36s |

速度候选只把接触推迟约 0.2–0.5 秒，没有改变胜率；因此已回退，正式规则继续使用 `3.96`。这避免把没有证据的修改带入真人试玩。

下一轮真人局优先观察“抓捕后从固定出生点重复追同一路线”。若少人数仍显著偏鬼，先在抓取轴比较复位后的保护/脱离机制，而不是同时修改伤害、电量和速度。4 名小孩目前存在明显更长的对局尾部，需记录这些局是成功围攻、找电池还是单纯拖到计时。

## 4. 信息、安全与稳定性

- 对 1、2、3、4 名小孩分别序列化每个小孩的 `ViewerFrame`；未显形时不存在鬼坐标、`randomState`、`ghostAction` 或 `phaseTicksRemaining`。
- 浏览器 `child-hidden` 状态的诊断对象也不含 `ghost` 字段，证明不是只在渲染层隐藏。
- 2–5 人真实 socket 房验证角色数与人偶数；双标签验证移动所有权、手电耗电、重连、鬼断线取消。
- 输入失焦、250 ms 服务端输入过期、事件去重、30 秒小孩重连和本地预测纠偏均有自动测试。
- 所有机器人局终止在规则终局内，无五秒全局停滞、永久重叠或非法穿墙证据。

## 5. 视觉测试

视觉 harness：已添加。

- 状态：`child-playing`、`ghost-playing`、`capture`、`child-win`。
- 固定条件：seed 71、暂停表现时间、减少运动、隐藏里程碑调试文字、等待字体与 GLB 完成。
- 视口：1280×720 Desktop Chrome；另测 1024×768 PC 笔记本 HUD 不重叠。手机不在首发范围。
- 阈值：`maxDiffPixelRatio: 0.008`，不使用 mask；画布、HUD、角色和导入资产都是验收内容。
- 基线：`tests/deterministic-states.spec.ts-snapshots/*.png`。
- 更新：`npx playwright test tests/deterministic-states.spec.ts --update-snapshots`。
- 比较：`npx playwright test tests/deterministic-states.spec.ts`。

人工查看基线后修复两项问题：给俯视角色增加低成本身份环；抓捕/保护期强制隐藏残留光束。暗房、门口、鬼全图镜头和结算层均保持可读。

## 6. 生产预览与渲染预算

在 `npm run build` 后使用 `vite preview` 的 4189 端口和正式房间服务开两页真实对局，再冻结后台页避免浏览器后台标签节流污染 FPS：

| 项目 | 实测 | 门槛 |
|---|---:|---:|
| FPS | 60 | ≥ 50 |
| Draw calls | 77 | ≤ 100 |
| Triangles | 42,666 | ≤ 100,000 |
| Geometries | 30 | ≤ 100 |
| Materials | 45 | ≤ 80 |
| Textures（含 renderer 内部分配） | 32 | ≤ 40 |
| Canvas | 1280×720 CSS / buffer | 非零且一致 |
| 像素亮度跨度 | 233 | > 20 |

- GPU：`ANGLE / Intel Arc B390 / Direct3D11`，`softwareRendered=false`。
- 活跃对象 218、可见角色 5、动画角色 4；Rogue Kid 7,562 三角面，墙段 478 三角面。
- 控制台错误 0、页面错误 0、资产失败 0、音频失败 0。
- 产物：`artifacts/canvas-inspection/report.json` 与 `desktop-active-match.png`（本地 QA 产物，不提交）。
- 首次测得 4 FPS 是两个无头页面同时活跃导致的后台页节流；固定前台页并冻结后台页后同一场景为 60 FPS，因此不把第一次采样当作设备性能。
