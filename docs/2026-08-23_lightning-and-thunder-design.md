# 打雷闪电机制设计

## 目标

闪电为对局增加短暂、不可预测且具有空间方向的显形机会。玩家应能通过房间变亮、墙体阴影、门洞光束和稍后到达的雷声判断闪电来源；规则判定与客户端画面应尽量使用同一方向和同一墙体几何。

本机制不绘制闪电本体，不扩展为完整天气系统，也不把闪电变成随机伤害。

## 对局规则

- 闪电只在正常 `playing` 阶段触发。首次触发与后续触发均等待 20–45 秒正常对局时间。
- 捕获动画和保护时间暂停闪电冷却；已经开始的闪电可以播完画面和雷声，但立即停止规则影响。
- 四个世界方向独立等概率抽取，允许连续重复。
- 闪电使用独立确定性随机流，不消费电池生成等既有玩法随机状态。
- 每次闪电包含 2–3 次无声预闪，每次持续 60–100 ms、间隔 70–140 ms；主闪持续 180–260 ms。
- 主闪后 0.2–1.2 秒播放雷声。过去的闪光和雷声不因重连或页面恢复而补播。

## 显形判定

- 权威端在每个对局 tick 重新判断鬼是否处于当前闪光的直射区域。
- 从闪电来源向鬼的左侧、中心和右侧发出三条水平平行采样射线；至少两条未被内墙阻挡时，鬼发生显形。
- 门洞是墙段之间的真实缺口，允许采样射线和画面中的直射光继续传播。
- 外墙不参与闪电遮挡，等价于光从未建模的外部开口进入；家具、真人玩家、感应人偶也不参与遮挡。
- 方向光没有空间距离衰减，也没有逐房间亮度倍率。墙只裁剪受光范围，不削弱穿过门洞的直射光强。
- 所有小孩玩家共享闪电显形结果；实际画面仍由墙体和镜头自然遮挡。
- 每次预闪和主闪都能触发显形。闪光结束后只保留约 0.25 秒的最后位置残影，不继续泄露鬼的新位置。
- 闪电显形与手电照射相互独立。闪电不造成伤害、灼烧或减速，不禁止抓捕，也不改变头灯档位。

## 权威状态与同步

- 权威 `MatchEngine` 决定下一次触发 tick、方向、闪烁节奏、雷声延迟和音频变体。
- 当前闪电的标识、开始 tick、方向和确定性节奏数据进入 checkpoint 与 viewer frame，保证 Socket.IO 房间主机、Harmony 房间主机和中途重连行为一致。
- 闪电开始事件用于一次性反馈；可恢复状态用于当前画面与规则。客户端从权威 tick 推导当前进度，不以消息到达时间重新起播。
- 重连时只继续尚未结束的阶段。已经过去的脉冲和雷声永不补播；尚未到达的雷声仍按原计划播放。

## 客户端表现

- 使用一盏持久但平时隐藏的冷白色投影 `DirectionalLight`，按四方向定位，以时间包络控制强度。
- 光线采用低俯角，使 2.8 m 墙体产生足够长的阴影；只有静态墙体参与闪电阴影。
- 所有边界外墙从闪电专用阴影层排除，内墙保留投影，门洞自然形成光束。
- 来源侧装饰窗随闪电同步增亮，用于提示方向。
- 不修改全局曝光，不使用环境光替代，不加全屏闪白，也不绘制天空电弧或光柱。
- 不提供减少闪烁设置，也不针对系统动态效果偏好改变闪电序列。

## 音频

- 使用三段具有明确 CC0 来源与许可证记录的真实雷声音效，加入现有单 JSON 音频包。
- 根据玩家朝向和闪电世界方向产生温和的左右声像。
- 雷声延迟越长，音量越低、低通越明显；延迟短时更响、更清脆。小范围确定性音高变化降低重复感。
- 音频仍服从现有首次交互解锁和静音按钮。音频尚未解锁或播放时机已经过去时不补播。

## 性能预算

- 桌面闪电阴影图使用 1024，Harmony 使用 512；实机不足时依次降低到 512 和 256。
- 墙体为静态遮挡物，阴影图只在方向改变时更新一次，同一次闪电的多个脉冲不重复计算。
- 闪电结束后隐藏灯光，避免持续阴影开销。
- 性能降级不得改为会穿墙的环境光或全屏闪白。

## 验收范围

- 权威规则：20–45 秒、四方向、允许连续重复、阶段暂停、三射线墙体判定、门洞透光和规则效果分离。
- 确定性：闪电随机流不改变电池等既有随机序列；checkpoint 恢复后调度与活动闪电一致。
- 联机：所有真人玩家共享事件方向和时间；中途重连从当前进度继续。
- 视觉：四个方向分别提供确定性主闪状态，验证来源房间、墙影、门洞光束、窗面反馈和不过曝。
- 音频：三种变体、方向声像、延迟参数、音频包一致性、许可证和零独立 MP3 请求。
- 性能：桌面浏览器诊断达标，并在 Harmony 真机记录闪电期间的帧率和阴影档位。
