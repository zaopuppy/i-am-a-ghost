## 模块与测试缝

`MatchEngine` 是与 DOM、Three.js、Socket.IO 和真实时间无关的深模块。调用方只需要了解两个操作：

1. `advance(commands, ticks)`：提交最新玩家意图并推进一个或多个固定 tick，返回本次事件和 checkpoint。
2. `checkpoint()`：读取服务器专用的完整权威状态副本。

规则测试只通过这个公开测试缝观察行为，不调用或 mock 碰撞、光束、抓取、随机数等内部实现。完整 checkpoint 仍然只供服务器和规则测试使用；`ViewerFrame.ts` 只定义鬼/小孩两类玩家视图的类型，实际安全投影在 M2 实现。

## 已实现规则

- 固定 60 Hz 的 XZ 平面移动；小孩速度 `3.6`，鬼速度 `3.96`。
- 半径 `0.45` 的真人圆形阻挡、地图边界和轴对齐矩形墙体，按轴移动产生滑墙。
- 感应人偶填满空缺的四个小孩槽位，但不参与碰撞、输入、抓取或胜负。
- 两个身长、20° 完整夹角的手电；墙体遮挡、8 秒满电和 20% 鬼减速。
- 鬼初始生命 `100`，单光束基础伤害 `12.5/s`；多光束倍率依次为 `1 / 0.65 / 0.45 / 0.3`。这些只是灰盒首轮值，不是平衡结论。
- 距离头灯使用 `6 / 4 / 2` 身长的慢闪、快闪和近常亮档位，不受墙体影响。
- 抓取范围 `1.4`、完整角度 90°、前摇 21 tick、抓空冷却 72 tick。
- 抓中后 90 tick 结算动画、全员复位和 120 tick 保护；期间冻结操作效果并暂停对局时钟。
- 任意小孩电量低于 15% 时按种子在合法点位生成唯一电池；只有小孩可拾取，复位保留场上电池。
- 五分钟即 18,000 个有效 tick；鬼生命归零或时间归零由小孩获胜，三次抓捕由鬼获胜。
- 每 tick 先结算光照伤害与时间，再结算抓取，保证致命光照与第三次抓捕同时发生时小孩优先。
- 同一种子和命令带产生完全相同的 checkpoint、事件 ID 和电池位置。

## 固定更新顺序

```text
接受并保持最新输入
  -> 预计算照射减速
  -> 真人移动、墙体与真人阻挡
  -> 手电耗电、遮挡、伤害和显形
  -> 电池拾取或生成
  -> 有效比赛时钟
  -> 小孩胜利条件
  -> 抓取前摇、命中或冷却
  -> 鬼胜利条件
```

抓捕动画和保护阶段走独立的暂停分支，不执行移动、照射、电池或比赛时钟。
