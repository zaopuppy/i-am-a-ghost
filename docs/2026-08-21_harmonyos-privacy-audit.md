# HarmonyOS 测试版本隐私审计

- 审计日期：2026-08-21
- 审计对象：`com.zero.gamehack.iamaghost` 的 HarmonyOS Gate A 原型及同仓库 Web/房间服务代码
- 结论性质：基于当前源码、当前生成的 HarmonyOS Web 资源和官方文档的静态审计；不是法律意见，也不能替代真机抓包、权限弹窗测试和发布包扫描。

## 结论摘要

当前 HarmonyOS 包没有发现账号登录、真实姓名/手机号/邮箱、通讯录、精确定位、麦克风、广告标识符、支付、推送、广告、行为分析或第三方崩溃上报。它的核心隐私数据是：局域网地址与附近游戏服务信息、随机临时昵称和游戏内标识、玩家实时操作/位置/对局状态，以及用户主动扫码后返回的二维码文本。

本次审计后已完成以下代码整改；房间码广播按产品决策保留：

1. **已修复：同意前不启动局域网能力。** `EntryAbility.onForeground` 不再自动启动 TCP/mDNS；Harmony 页面先展示本次运行的局域网数据处理说明，用户勾选后才启动，取消勾选、切到后台或退出时停止并清空。本次同意不落盘，因此不会成为新的备份/迁移数据。四部门《App违法违规收集使用个人信息行为认定方法》将“征得用户同意前就开始收集个人信息或打开可收集个人信息的权限”列为可能的违规情形：[官方原文](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/rzjgs/art/2023/art_71e1f20c15e848428b218b88a4407ed4.html)。
2. **已按产品决策保留：附近设备广播房间码并支持一点即加入。** 房间码用于低摩擦的附近房间发现，不作为个人信息或高强度鉴权凭据。局域网协议仍是明文 TCP，同一网络内设备可看到房间元数据并尝试入房；这是当前测试版明确接受的访问控制取舍，不应在政策中宣传为“加密传输”或“仅受邀者可见”。
3. **已修复：禁用应用数据迁移。** 已删除备份扩展、备份配置和 `CoreFileKit` 备份代码；生成的模块清单不再包含 `extensionAbilities` 备份项。
4. **已修复：Release 自动硬化。** 新增 `prototype:harmony:release` 命令，自动选择 Vite/Hvigor release 模式；Release 关闭 ArkWeb 调试、前端 source map、Web 文件访问和 DOM Storage，并移除前端控制台代码。原生网络详细日志只在 `BuildProfile.DEBUG` 为真时输出。
5. **按要求暂不修改：签名配置仍被 Git 跟踪。** 其中包含开发者主目录绝对路径和加密形态的密钥库口令字段（不要在政策中披露具体值；证据：`prototypes/harmony-gate-a/build-profile.json5`）。这不是隐私政策条款，但仍是发布工程的凭据管理风险。

### 不应夸大为“收集”的内容

- 当前应用**没有让用户填写昵称**；昵称是“形容词 + 访客 + 三位数”的随机值（`src/main.ts:1035-1038`）。政策可写“随机临时昵称”，不要写“您主动提供的昵称”。
- 扫码使用系统默认界面。华为说明该能力已预授权相机并处于安全访问状态，开发者不必另申请 `ohos.permission.CAMERA`，系统首次使用还会显示隐私横幅；应用代码只取得扫码结果，不取得相机帧或相册全库（`Index.ets:87-92`；[默认界面扫码](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V13/scan-scanbarcode-V13)）。
- `https://game.local/` 是映射到包内 `rawfile/game` 的虚拟来源，不是开发者的互联网服务器；请求被 `onInterceptRequest` 返回本地资源（`Index.ets:7-9, 137-156, 169-205`）。

- **Web 组件文件与 DOM 存储开关**：二者是 ArkWeb 能力开关，不是 `module.json5` 系统权限；当前均已设为 `false`。华为文档说明二者分别控制 Web 文件系统访问和 DOM Storage：[Web 页面加载说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/web-page-loading)。

相机清单权限、麦克风、定位、通讯录、短信、电话、日历、蓝牙、通知、健康/传感器、设备唯一标识符、账号、剪贴板读取、悬浮窗、后台持续运行。源码中的剪贴板调用只出现在开发调试/场景编辑器写入功能，生产 Harmony 构建的 `import.meta.env.DEV` 分支不可达（`src/main.ts:82-86, 271-273, 828-848`）。

## 3. 本地、局域网与服务端保存

### 当前 HarmonyOS 安装包路径

- 游戏房间、玩家、操作帧、扫码结果和附近房间都保存在内存对象/Worker 中，没有业务数据库或文件写入。离开前台会停止 mDNS/TCP，清空连接、缓冲区、收件箱和附近房间（`EntryAbility.ets:79-81`；`LanHostProbe.ets:290-340, 420-435`）；Web 文档隐藏时也会重置会话并关闭房间 Worker（`src/net/HarmonyLanGameClient.ts:338-365`）。
- 当前生成的 Harmony JS 产物仍包含 Socket.IO 和浏览器 `sessionStorage` 后备代码，因为客户端会在原生桥不可用时运行 `GameClient`；正常桥接成功时选择 `HarmonyLanGameClient`，不会执行该后备路径（`src/main.ts:79-95`，`src/net/GameClient.ts:27-55, 172-238`）。产物未包含仅开发模式使用的场景草稿 `localStorage` 键。每次发布仍应抓包验证原生桥失败时不会出现非预期外联。
- 扫码状态采用“读取即消费”：Web 取走成功、取消或失败状态后，原生层立即复位为 `{ state: 'idle', payload: null, error: null }`。
- 已删除备份 ExtensionAbility 及其配置，且 Web DOM Storage 关闭。本版本不通过 HarmonyOS 应用备份迁移业务数据。

### 仓库中的 Web/中心房间服务备用路径

这不是当前 Harmony 原生局域网运行路径，但如果未来把同一客户端指向互联网服务器，隐私政策必须更新：

- Web 客户端会把房间会话（房间码、玩家 UUID、重连令牌、房主标记）和随机昵称写入 `sessionStorage`，标签页会话结束或代码清理后失效（`src/net/GameClient.ts:27-55, 172-238`）。
- Node/Socket.IO 房间服务器把昵称、玩家 ID、重连令牌、Socket ID、输入和游戏状态只存在进程内存；断线重连宽限为 30 秒，空房间约 30 秒后清除（`server/GameRoom.ts:68-109, 194-272`；`server/RoomManager.ts:17-29, 140-146`；`src/net/protocol.ts:10-11`）。未发现数据库或持久化写入。
- 服务器 CORS 接受任意来源，且示例服务默认监听 `0.0.0.0`（`server/createGameServer.ts:39-47`；`server/index.ts:1-4`）。若暴露到互联网，必须增加明确域名、TLS、访问控制、日志与实际保留期，并在政策中写明服务器运营方、地点和共享/委托处理关系。

## 4. 第三方代码、SDK 与共享对象

### 代码依赖

- Harmony 模块的 OHPM 依赖为空（`prototypes/harmony-gate-a/entry/oh-package.json5:1-9`，`prototypes/harmony-gate-a/oh-package.json5:1-5`）。
- Web 源码声明运行依赖 `three`、`qrcode`、`socket.io`、`socket.io-client`（`package.json:30-35`）。当前 Harmony 路径使用 Three.js 在端内渲染、`qrcode` 在端内生成房间二维码；Socket.IO 是浏览器/中心服务器备用路径。未发现这些库自行收集或上报设备/个人信息的调用。
- 使用的系统 Kit 包括 AbilityKit、ArkUI/ArkWeb、NetworkKit、ScanKit、PerformanceAnalysisKit。它们是 HarmonyOS 平台能力，不等于仓库新增的营销/分析 SDK；但 AGC 的“第三方 SDK/服务”模块建议保守披露 **华为 Scan Kit（统一扫码服务）**，说明仅在用户主动扫码时调用、处理相机预览或用户选中图片并返回码值，链接其[官方能力说明](https://developer.huawei.com/consumer/en/doc/harmonyos-guides-V13/scan-scanbarcode-V13)。

### 实际共享/接收对象

1. **同一局域网的房主设备**：接收加入者的随机昵称、玩家标识、操作帧；处理房间规则。
2. **同房其他玩家设备**：接收房间成员随机昵称、玩家 ID、角色/连接/准备状态，以及按玩家视角生成的游戏帧和事件。
3. **同一局域网的附近设备**：即使未加入，也可看到 mDNS 服务与探测响应中的房间连接元数据。
4. **华为系统 Scan Kit**：用户主动扫码时处理相机/所选图片，并把码值结果返回应用。
5. **开发者服务器**：当前 Harmony 局域网版本没有业务数据上传到开发者服务器；不要在 AGC 中虚构云端保存或跨境传输。

AppGallery Connect 的测试用户华为账号、邀请关系和下载记录由华为分发平台处理，不是当前 App 代码收集的业务数据；若开发者另行用表格、群聊或邮件收集测试者资料，应在相应渠道单独告知。

## 5. 日志、保留期与删除

建议把政策中的保留期写成当前实现能兑现的具体规则：

- 附近房间、局域网端点、玩家和对局数据：仅在应用前台/房间运行期间存于参与设备内存；后台、关闭房间或进程结束后清除。
- 二维码解码文本：仅用于本次加入房间，读取后立即从原生扫码状态中清空。
- 系统日志：Release 不输出 IP、端口、附近服务、Web 控制台和原始网络错误等详细诊断；Debug 包仍可输出并仅进入本机系统日志。
- 应用备份：可写“本版本不通过 HarmonyOS 应用备份迁移业务数据”。
- 当前无账号体系，因此无需“注销账号”，但仍要提供隐私政策入口、撤回同意/停止局域网处理的方式和联系方式。四部门规则要求提供删除/更正渠道及投诉举报方式：[官方认定方法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/rzjgs/art/2023/art_71e1f20c15e848428b218b88a4407ed4.html)。

《个人信息保护法》第十七条要求告知处理者名称/联系方式、目的、方式、种类、保存期限和权利行使方式；第十九条要求保存期限为实现目的所必要的最短时间：[官方全文](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2023/art_f374e8245320413181742e6d1baf4366.html)。

## 7. AppGallery Connect 填写建议

华为的托管隐私政策页面要求逐项填写“个人信息收集使用、设备权限、未成年人、第三方共享、第三方 SDK、个人信息管理、存储地点及期限、联系方式、生效日期”，且实际行为变化后要更新：[配置隐私政策（HarmonyOS 应用）](https://developer.huawei.com/consumer/cn/doc/doccenter-submission/agc-help-privacy-policy-app-0000002282162168)。

### “我们如何收集和使用您的个人信息”

建议拆成三个功能，不要写成“为改善体验收集设备信息”这种笼统表述：

1. **局域网房间创建与发现**  
   信息：本机及附近房间的局域网 IP、端口、mDNS 服务名、房间码、实例 ID、玩家数量和连接状态。  
   目的：发现、创建和连接同一局域网内的游戏房间。  
   方式/频率：用户勾选本次运行的局域网联机说明后，在应用前台持续发现；创建或加入房间时处理。  
   保存：参与设备内存，后台/关闭房间后清除；不上传开发者云服务器。
2. **多人游戏同步**  
   信息：程序生成的临时昵称、玩家/房间/对局标识、角色和准备状态、移动方向、朝向、动作、游戏位置及对局事件。  
   目的：区分同房玩家并进行实时对局同步。  
   方式：通过同一局域网发送至房主设备并向同房玩家返回必要状态。  
   保存：房间运行期间的内存；关闭后清除。
3. **扫码加入房间（可选）**  
   信息：系统 Scan Kit 从相机或用户选中图片识别出的二维码文本；当前合法游戏码包含局域网 IP、端口、房间码和实例 ID。  
   目的：快速加入房间。  
   方式：仅用户点击扫码后调用；拒绝/取消不影响手动输入房间码。  
   保存：仅用于本次连接；Web 读取扫码状态后立即清除原生层码值。

### “设备权限调用”

- 网络访问：同一局域网创建/发现/加入房间及同步对局。
- 获取网络信息：判断可用网络并取得创建房间所需局域网地址。
- 扫码能力说明：用户主动使用扫码加入时，系统 Scan Kit 安全访问相机；选择相册图片时只处理用户主动选中的图片。当前包不申请 `CAMERA` 或广泛相册读取权限。

### “与第三方共享”

不能笼统承诺“数据绝不向其他设备提供”。应在个人信息收集使用章节明确：用户主动联机时，必要数据会传给房主设备和同房玩家设备，并列出最小字段；同一局域网的附近设备可收到房间发现元数据，包括房间码。若 AGC 的“与第三方共享”模块只接受企业/机构接收方，不要虚构一个企业接收者；可选择“无第三方商业共享”，并在自定义章节说明这是用户主动发起的点对点传输。

### “第三方 SDK”

- 建议列：华为 Scan Kit（统一扫码服务），提供方华为，目的为用户主动扫码加入房间，处理相机预览或用户所选图片并返回二维码文本，调用时机为用户点击扫码。
- Three.js、`qrcode` 可列入“开源组件”附录，说明端内渲染/端内生成二维码且未观察到独立个人信息上报。
- 不要列入未实际集成的 AGC 分析、崩溃、推送、广告、账号 SDK。

### “信息存储地点及期限”

建议填写“个人信息主要在用户参与联机的 HarmonyOS 设备内存及同一局域网参与设备间处理，不上传开发者服务器；用户撤回局域网同意、应用后台、关闭房间或进程结束后清除。本版本不通过 HarmonyOS 应用备份迁移业务数据”。

### “管理您的个人信息”与“如何联系我们”

- 产品内提供始终可访问的隐私政策入口和“停止局域网功能/退出房间”入口。
- 填入真实的个人信息处理者名称、可用邮箱或其他联系方式，以及删除/投诉处理流程；这些运营信息无法从源码推断，必须由发布主体补充。
- 当前无账号，不应虚构账号注销；可以写“本应用不提供账号注册。如需查询或删除仍在处理的数据，请退出房间/关闭应用，或通过以下联系方式提出请求”。

### “未成年人保护”

需要发布主体确认目标年龄和是否会明知处理未满 14 周岁用户信息。若可能，应选择合适年龄分级，提供监护人同意和专门规则；仅写一句“未成年人请在监护人指导下使用”可能不足以覆盖实际处理。

## 8. 发布主体仍需确认的事实

以下内容不能从代码得出，提交前必须由负责人填写并留档：

- 个人信息处理者的法定名称、注册地址、隐私联系邮箱/电话；
- 发布地区、测试者是否包含未满 14 周岁人员；
- Debug 测试包的系统日志接触范围及测试设备的日志清理策略；
- 是否部署/使用 `server/` 中心服务器；若使用，服务器地址、运营主体、机房地区、TLS、日志内容和保留期限；
- 是否通过群聊、问卷、邮件等 App 外渠道收集测试者姓名、手机号、邮箱或反馈；
- 发布包最终依赖清单、是否加入任何 AGC/HMS 分析、崩溃、推送、广告或账号能力；
- 第三方服务合同、数据处理协议、开源许可证与安全评估记录。

## 9. 建议的发布前验证

1. 用 `npm run prototype:harmony:release` 重新构建 `.app` 并做静态权限/SDK 扫描，确认只有 `INTERNET` 和 `GET_NETWORK_INFO` 清单权限。2026-08-21 本地验证的生成清单为 `buildMode: release`、`debug: false`，且 Web 资源中没有 `.map`；每次正式上传仍需复核最终产物。
2. 首次安装后在未同意隐私政策时抓包，确认没有 mDNS、TCP 监听、附近探测或外联；同意后再出现。
3. 两台设备联机并由第三台同网设备观察，记录 mDNS/TCP 明文字段和一点即加入行为，确认它们与隐私告知及本报告的已接受风险一致。
4. 分别用相机扫码和相册扫码，确认系统隐私提示、拒绝/取消路径及扫码结果即时清理。
5. 检查 release hilog、崩溃日志和 Web 控制台，确保不含 IP、端口、昵称、玩家 ID、令牌、二维码文本或游戏帧。
6. 检查最终 HAP/HSP/APP 是否包含 `.map`、调试开关和非预期网络端点；验证卸载、后台、退出房间、数据克隆后的数据残留。
