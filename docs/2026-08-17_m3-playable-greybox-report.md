# M3 可玩灰盒报告

## 玩家体验闭环

- 玩家承诺：孩子在黑暗大宅中靠短光束协作求生，鬼从全局视野寻找抓取窗口。
- 核心循环：移动与判断距离 → 孩子冒险照射/鬼逼近抓取 → 消耗电量或累计抓取 → 电池争夺与位置重置 → 五分钟或三次抓取结算。
- 失败与重试：抓到后播放 1.5 秒阶段反馈，所有真人回到初始位置，再进入 2 秒保护期；结算后所有真人点击准备，下一局自动开始并轮换鬼。
- 非目标：本阶段不引入账号、数据库、开关门、移动端、语音聊天或复杂物理引擎。

## 场景与镜头

- 房屋扩大为 32 × 20 个游戏单位，包含九个命名房间、多个窄门口、两条可循环路线和西北/东南两处死角。
- 碰撞继续使用确定性的圆形真人代理与 AABB 墙体；该玩法不需要刚体、斜坡或堆叠，因此没有引入额外物理引擎。
- 鬼使用 22.5 单位高的全屋正交镜头；孩子使用 10.5 单位高的平滑跟随镜头。
- 深色地面只提供轻微房间分区，墙体顶边承担导航；孩子端未照中的鬼实体根本不存在于帧和场景中。

## 世界反馈与 HUD

- 四种暖色小孩占位体、人偶、无脚的程序化鬼、电池与两身长/20° 手电锥均已可视化。
- 头灯按 `off / slow / fast / solid` 四档闪动，距离判断仍完全来自服务端且无视墙体。
- HUD 固定显示五分钟计时、鬼血条和三格抓取计数；仅孩子显示自己的电量，鬼端不接收任何孩子电量。
- 抓取动画、保护期、低电量和最终胜负分别有独立的形状、颜色或文本反馈；`prefers-reduced-motion` 会关闭低电量闪动。

## 验收证据

- 规则/服务端测试覆盖五分钟胜负、三次抓取、暂停/重置/保护、墙体阻挡、手电遮挡、电池、人偶和轮换。
- 双浏览器测试验证两种镜头、九房间场景、HUD、ESDF 移动、空格光束和电量消耗。
- `npm run build`、`npm run test:rules`、`npm run test:browser` 均通过。

## 仍待后续阶段

M3 仍使用占位角色且采用直接显示服务端帧。M4 将加入断线人偶/30 秒重连、输入过期、预测、插值与纠偏；M5 再替换为 CC0 角色和音频并做技术美术收口。
