# 房屋场景编辑器

开发服务器运行时打开：

```text
http://127.0.0.1:5189/?sceneEditor=1
```

生产构建不会启用编辑器。编辑中的草稿保存在当前浏览器的 `localStorage`，刷新页面后仍会恢复；「复原」会恢复仓库内的默认场景。

左侧面板和场景视口采用并排停靠布局，不会遮住地图。标题栏的箭头可以收起面板，让视口扩展到几乎整个窗口。

## 视口导航

- 编辑对象：左键选择并拖动家具、房间或墙体。
- 漫游地图：左键平移视口，避免误拖场景对象。
- 两种模式下均可使用右键旋转、中键平移、滚轮缩放。
- 「适配全屋」或 `F` 会恢复俯瞰角度并让整栋房屋进入视口。
- `V` 可以快速切换编辑对象与漫游地图模式。

## 编辑能力

- 家具：选择、拖动、跨房间移动、替换模型、旋转、缩放、调整离地高度、增加和删除。
- 房间：拖动中心点，编辑名称、风格、宽度和深度。家具使用房间内相对坐标，因此移动房间时会一起移动。
- 墙体：选择、拖动、调整宽度和深度、增加和删除墙段。
- 出生/刷新点：紫色鬼脸环是鬼出生点，黄色电池环是电池候选刷新点；两者都可以拖动或输入世界坐标，并参与实时校验。绿色圆环是只读的小孩出生点。
- 历史：按钮或 `Ctrl+Z` / `Ctrl+Y` 撤销和重做。
- 数据：复制、下载或重新导入版本化 JSON。

家具快捷键：`Q` / `E` 旋转 15°，`R` 旋转 90°，`Delete` 删除当前对象。

视口中的青色细框是墙内侧的真实房间范围；青色半透明色块是家具移动碰撞脚印，选中后会变成黄色；橙色色块是门洞安全区。默认九个房间分别按照三列墙体的真实内宽 `10.7 / 9.8 / 10.7m` 和三行墙体的真实内深 `6.2 / 6.8 / 6.2m` 建立，因此家具可以贴到墙内侧而不会产生错误的越界提示。

墙纸使用 `1.2m × 1.4m` 的世界尺寸平铺，并以世界坐标对齐相邻墙段。移动或改变墙体宽度、深度时只会显示更多或更少的重复纹样，不会拉伸或压缩墙纸；编辑器与正式游戏使用同一套材质和 UV 规则。

## 校验与碰撞

场景编译模块会在每次修改后重新生成房间、门洞和家具碰撞脚印，并检查：

- 重复 ID、未知房间和未知家具模型；
- 实体家具是否越过所属房间；
- 门洞安全区、角色出生点和电池刷新点是否被占用；
- 出生点和电池刷新点是否侵入墙体或地图边界；
- 所有出生点和电池点在计入家具碰撞后是否仍然连通；
- 同一房间的家具碰撞脚印是否重叠。

存在错误时禁止复制或下载。警告允许导出，但应人工确认。地毯、画框和桌面灯等装饰物没有移动碰撞；床、桌、椅、沙发、柜子和书架使用独立于 GLTF 网格的二维脚印。

「当前问题」显示的是尚未解决的实时校验结果，不是不断累积的历史日志。可以筛选全部问题、家具越界、错误或警告；点击条目会选中对象并把镜头移动到它的位置。「清除已读」只隐藏当前筛选结果，不会绕过校验或重新启用导出；「恢复」会重新显示隐藏的问题，任意场景修改也会重新计算并显示仍然存在的问题。

家具只阻挡角色移动，不会被当作整面墙遮断手电判定。服务器权威模拟、客户端预测和自动平衡机器人共用同一个碰撞模块。

## 保存为默认地图

编辑器导出的 JSON 是完整 `HouseSceneDefinition`。仓库当前默认场景的唯一数据源是：

```text
assets/maps/m3-nine-room-house.scene.json
```

将编辑器下载的同名文件复制到该路径并覆盖原文件，然后运行：

```powershell
npm run validate:map
npm run build
npm test
npm run test:balance
```

`npm run validate:map -- assets/maps/其他地图.scene.json` 可以校验任意尚未设为默认的地图。默认文件改变后需要重启 `npm run dev`；客户端、房间服务器、编辑器「复原」和自动平衡模拟随后都会读取新地图。

编辑器本身不会直接写入仓库，避免浏览器中的误操作覆盖默认地图。浏览器 `localStorage` 中已有的编辑草稿也不会被自动覆盖；如需查看新的仓库默认地图，请在编辑器中点击「复原」。
