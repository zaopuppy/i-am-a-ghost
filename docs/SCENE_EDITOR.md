# 房屋场景编辑器

开发服务器运行时打开：

```text
http://127.0.0.1:5189/?sceneEditor=1
```

生产构建不会启用编辑器。编辑中的草稿保存在当前浏览器的 `localStorage`，刷新页面后仍会恢复；「复原」会恢复仓库内的默认场景。

## 编辑能力

- 家具：选择、拖动、跨房间移动、替换模型、旋转、缩放、调整离地高度、增加和删除。
- 房间：拖动中心点，编辑名称、风格、宽度和深度。家具使用房间内相对坐标，因此移动房间时会一起移动。
- 墙体：选择、拖动、调整宽度和深度、增加和删除墙段。
- 历史：按钮或 `Ctrl+Z` / `Ctrl+Y` 撤销和重做。
- 数据：复制、下载或重新导入版本化 JSON。

家具快捷键：`Q` / `E` 旋转 15°，`R` 旋转 90°，`Delete` 删除当前对象。

## 校验与碰撞

场景编译模块会在每次修改后重新生成房间、门洞和家具碰撞脚印，并检查：

- 重复 ID、未知房间和未知家具模型；
- 实体家具是否越过所属房间；
- 门洞安全区、角色出生点和电池刷新点是否被占用；
- 所有出生点和电池点在计入家具碰撞后是否仍然连通；
- 同一房间的家具碰撞脚印是否重叠。

存在错误时禁止复制或下载。警告允许导出，但应人工确认。地毯、画框和桌面灯等装饰物没有移动碰撞；床、桌、椅、沙发、柜子和书架使用独立于 GLTF 网格的二维脚印。

家具只阻挡角色移动，不会被当作整面墙遮断手电判定。服务器权威模拟、客户端预测和自动平衡机器人共用同一个碰撞模块。

## 保存为默认地图

编辑器导出的 JSON 是完整 `HouseSceneDefinition`。当前仓库的默认场景保存在 `src/game/defaultHouseScene.ts`；确认导出结果后，可将其中的房间、墙体、家具和刷新点数据替换为导出内容，并运行：

```powershell
npm run build
npm test
npm run test:balance
```

编辑器本身不会直接写入源码，避免浏览器中的误操作覆盖仓库文件。
